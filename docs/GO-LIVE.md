# التشغيل الفعلي — ما تبقّى لتشغيل هبّة

كل ما في التطبيق مبنيّ ومختبَر. ما يلي هو ما يحتاج **حساباتك ومفاتيحك** فقط: مشروع
Supabase، ومزوّد الرسائل (OTP)، وبوابة الدفع. لا شيء هنا يتطلّب تعديل منطق التطبيق،
باستثناء خطوة واحدة موضّحة في «الدفع» (نموذج البطاقة من Moyasar).

التفاصيل التقنية لكل خطوة في `docs/supabase-setup.md` — هذا الملف هو القائمة.

---

## 1. مشروع Supabase

1. أنشئ المشروع (قرار المنطقة في ADR-0010 — لا يُغيَّر بعد الإنشاء).
2. طبّق الترحيلات: `supabase-setup.md` §4 (من 0001 إلى آخر ترحيل، بالترتيب).
3. سياسات التخزين: §7.
4. تحقّق: `pnpm test:rls:hosted-shape` يمرّ على المشروع (§6).

**في التطبيق** (`apps/mobile/.env.local`، أو متغيّرات EAS):

| المتغيّر                               | من أين                            |
| -------------------------------------- | --------------------------------- |
| `EXPO_PUBLIC_SUPABASE_URL`             | Settings → API                    |
| `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Settings → API Keys (publishable) |
| `EAS_PROJECT_ID`                       | `eas init` — للإشعارات            |

بمجرّد ضبطها يعمل التطبيق على قاعدة البيانات الحقيقية بدل وضع التجربة، ويبقى
تسجيل الدخول محفوظاً في Keychain بعد إغلاق التطبيق.

## 2. رمز التحقّق (OTP) بالرسائل

الرمز يولّده ويتحقّق منه Supabase Auth؛ الإرسال عبر دالة `send-sms-hook` إلى
Unifonic. التفاصيل: `supabase-setup.md` §5.

```bash
supabase functions deploy send-sms-hook --no-verify-jwt
supabase secrets set UNIFONIC_APP_SID=… UNIFONIC_SENDER_ID=… SEND_SMS_HOOK_SECRET=v1,whsec_…
```

ثم في لوحة Supabase:

- Authentication → Providers → **Phone**: فعّله، طول الرمز **6**، الصلاحية **120 ثانية**
  (يطابقان `OTP_LENGTH` و `OTP_TTL_SECONDS` في `otp-provider.ts`).
- Authentication → Hooks → **Send SMS**: اختر الدالة `send-sms-hook` وانسخ السرّ
  إلى `SEND_SMS_HOOK_SECRET`.
- **اسم المرسِل** يجب أن يكون معتمداً لدى Unifonic وهيئة الاتصالات (§5b)،
  وإلا لن تصل الرسائل رغم نجاح الطلب.

البريد الإلكتروني (اختياري، §5c): فعّل مزوّد Email واجعل القالب يرسل `{{ .Token }}`.

## 3. الدفع (Moyasar)

كل الجانب الخادم جاهز ومختبَر (الترحيل 0077، الدالة `payments`، السلسلة 49):
الخادم يتحقّق من كل دفعة لدى Moyasar بالمفتاح السرّي — المبلغ بالضبط، بالريال،
ولهذا الطلب — ولا يقبل كلام الجوال أبداً. التحصيل والإلغاء والاسترداد تنفّذها
الدالة من طابور.

**الخطوة الوحيدة في الكود:** نموذج البطاقة على الجوال. يحتاج SDK من Moyasar
(كود أصلي، لا يعمل في Expo Go) — المكان والإعدادات المطلوبة موثّقة في:

```
apps/mobile/src/features/shared/lib/moyasar-card-form.ts
```

(أهمّها: `manual: true` للحجز دون خصم، و`metadata: { order_id }` — الخادم يرفض
أي دفعة بدونها.)

ثم:

```bash
supabase functions deploy payments
supabase secrets set MOYASAR_SECRET_KEY=sk_live_… HABBA_PAYMENTS_TICK_SECRET=…
```

- جدولة الطابور كل 30 ثانية: `supabase-setup.md` §7b.
- قبل التفعيل وبعد أي تعديل على الدالة: `pnpm api:start && pnpm test:payments-e2e` يشغّلها فعلياً
  (Deno) أمام قاعدة البيانات المحلية وMoyasar وهمي — 16 فحصاً للحجز والرفض والتحصيل.
- في التطبيق: `EXPO_PUBLIC_MOYASAR_PUBLISHABLE_KEY=pk_live_…` ثم build جديد
  (`pnpm --filter @habba/mobile build:preview`).
- **آخر خطوة:** في لوحة التشغيل ← الإعدادات ← الدفع، غيّر «بوابة الدفع» من `dev`
  إلى `moyasar`. قبلها لا شيء من هذا على مسار الدفع؛ بعدها لا يُقبل أي حجز إلا
  عبر الخادم.

**الفاتورة الأعلى من المحجوز محلولة (0078):** لما قطع الغيار ترفع الإجمالي عن
المبلغ المحجوز عند الطلب، شاشة تأكيد الإنجاز تعرض الفرق، والعميل يحجزه بنفس
الضغطة («احجز الفرق وأكّد الإنجاز»)، وكل حجز يُحصَّل بقيمته. لو أغلق مشغّل أو
الإغلاق التلقائي الطلب دون الفرق، يظهر الجزء غير المغطّى للمشغّل في «المالية».

⚠️ ما زال مفتوحاً — ADR-0008 (قرار قانوني): هل يحقّ لهبّة حجز الأموال وصرفها
للفنيين، أم يلزم ترخيص من ساما؟ وصلاحية الحجز على البطاقة ~7 أيام؛ الحجز
المبكّر جداً لموعد بعيد قد ينتهي قبل التحصيل.

## 4. الدوال المجدولة

| الدالة          | ماذا تفعل                             | كل              |
| --------------- | ------------------------------------- | --------------- |
| `dispatch-tick` | توسيع البحث عن فنّي، إغلاق الطلبات    | 15 ثانية        |
| `push-tick`     | إرسال الإشعارات                       | دقيقة + webhook |
| `payments`      | تحصيل/إلغاء/استرداد (بعد تفعيل الدفع) | 30 ثانية        |

الأوامر: `supabase-setup.md` §7a و§7b.

## 5. لوحة التشغيل

`apps/admin/README.md` — النشر على Vercel بمتغيّرات البيئة فقط. المفتاح السرّي
لا يصل للمتصفّح أبداً (يفشل البناء لو حدث).

## 6. قبل أول مستخدم

- `pnpm verify` أخضر.
- جرّب على جوال حقيقي: تسجيل برقم حقيقي ← طلب طوارئ من حساب، وقبوله من حساب
  فنّي آخر ← الإنجاز والتقييم ← الفاتورة.
- `supabase-setup.md` §10.
